## Method

1. **Mechanical pre-pass.** An out-of-tree ASAN+UBSAN build ran the corpus
   flows fully instrumented (clean — zero engine reports) and a UBSAN build
   ran the full suite (clean; the sole hit was a build-recipe artifact, see
   *Environment notes*). `ruff` (F, B, PLE, PLW) seeded the Python finders
   with the B023/B905/F841 clusters.
2. **Find.** 22 scope×lens finder agents over the file inventory (containers
   /arithmetic/lifetime/pybind-boundary/SQL/parsers/geometry for C++;
   state-sync/index-remap/exception-swallowing/snapshot-restore for Python;
   converters for tools), each carrying the known-issue exclusion baseline
   (opens.md, wishlist-*, xfail'd tests) so documented issues are not
   re-reported. 98 raw findings → 93 after mechanical dedup.
3. **Verify + fix.** Each queued finding was re-verified in-session with a
   concrete probe before any code changed; fixes were written
   failing-test-first, one commit per finding. Batch gates: fast tier per
   fix, mid tier + corpus diff (normalized for timing/tmp-names) per ~5
   fixes. Delicate zones (planner scoring) went LAST under a 5-flow corpus
   A/B protocol. tools/ findings were scoped report-only by decision.

### The C7-04 deep dive (the suite's own segfault)

While validating a fix batch, the fast tier began segfaulting
intermittently (~30% of runs, ~75% under `MALLOC_PERTURB_`). Isolation:
clean on origin/main, triggered by a new audit test whose only sin was
perturbing heap layout. `pystack` on a core dump pinned the crash to
`buda.topo_uid(c)` inside `_merge_more_candidates`' fresh-candidates loop;
gdb showed the Topology's string data pointing into glibc's `main_arena` —
a freed object behind a live Python handle.

Root cause: `w.input.candidates` (and `NUTSResult.dogleg_topologies`)
element access handed back **registered non-owning views** (pybind's stl
caster propagates `def_readwrite`'s `reference_internal` policy to
elements). A view held across any pool reassignment dangles — and worse,
its stale instance-registry entry at the freed address makes a *later* cast
of a fresh temporary Topology landing at a recycled address return the
STALE object instead of the new value. Fix at the binding seam: by-value
getters (owned copies), write-back at the three in-place mutation sites,
and the Codex #176 guard test inverted to pin the new contract. PR #321's
engine-ctor `keep_alive` fixed the sibling hazard of this family; C7-04
closes the container-element side. Verified: 8/8 perturbed full-tier runs
clean (was 3/4 segfault), corpus byte-identical.

**Residual class note:** other registered-class container members
(`Topology.segments`, `seg_busterms`, …) still yield element views. No
crash is known through them; converting them wholesale is a
binding-breaking sweep left as a wishlist item.

## Environment notes (not BUDA bugs; feeds the BUDA_SANITIZE option)

- **PRE-1**: the UBSAN full-suite segfault was GCC 13.3 miscompiling
  hashtable `equal_range` when LTO objects compiled at `-O3 -march=native`
  are relinked at `-O1` (the scratch build's flag mismatch). BUDA bindings
  exonerated (healthy registry in gdb; 200-iteration churn clean on the
  normal build). Sanitized configs must keep compile/link opt levels
  identical or disable LTO.
- `pybind11_add_module`'s default LTO + post-build strip clash with ad-hoc
  sanitizer flags (an `-fno-lto` link over LTO objects produced an *empty*
  module). Working recipe: `CMAKE_BUILD_TYPE=Debug` (skips pybind's LTO and
  strip) + `-fsanitize=address -O1 -g`.
- `LD_PRELOAD` libasan on this gcc-13/glibc CHECK-fails on the first C++
  throw from any dlopen'd module — unusable for the pytest suite (BUDA's
  own fail-LOUD throws trip it); fine for throw-free standalone repros.
- `test/tests/conftest.py` force-inserts `build/` at `sys.path[0]`, so
  alternate-build testing needs a build-dir swap (or symlink).
