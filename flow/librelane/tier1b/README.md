# Tier 1b — a Gemmini mesh at N = 4, 8, 16

The tier-1a array with real RTL from somebody else: Gemmini's systolic mesh,
generated by Chipyard at three sizes.  `Mesh` instantiates `Tile` which
instantiates `PE` — the repeated cells — and the generated Verilog keeps them
as repeated modules (FIRRTL deduplicates structurally identical modules by
default), which is the shape the hierarchical arms need.

Nothing here has been run: this tree has no Scala toolchain.  The recipe is
written against Chipyard's documented setup and Gemmini's `CustomConfigs.scala`
(`GemminiCustomConfigs.defaultConfig.copy(meshRows = …, meshColumns = …)` is
Gemmini's own way of resizing the array; `GemminiRocketConfig` in
`generators/gemmini/chipyard/GemminiConfigs.scala` is the composition copied
here).  Chipyard is "developed and tested on x86 Linux"; on the Mac, run it in
a Linux container.

```bash
# 0. A Linux shell with ~30 GB free (on macOS: docker run -it -v $HOME:$HOME ubuntu:22.04 bash,
#    then apt-get install -y git curl build-essential).  Chipyard installs its own
#    conda + JDK + sbt + firtool; nothing else is needed to GENERATE Verilog.
git clone https://github.com/ucb-bar/chipyard.git ~/chipyard && cd ~/chipyard
./build-setup.sh riscv-tools -s 6 -s 7 -s 9     # skip FireSim, FireMarshal, cleanup; keep the toolchain step
                                                #   only if you also want to SIMULATE (it is the slow part)
source env.sh

# 1. The three mesh sizes as Chipyard configs.
cp ~/src/buda/flow/librelane/tier1b/BudaGemminiConfigs.scala generators/chipyard/src/main/scala/config/

# 2. Generate Verilog (no simulation): per-module .sv files land in gen-collateral/.
cd sims/verilator
for N in 4 8 16; do make verilog CONFIG=BudaGemminiMesh${N}RocketConfig; done
ls generated-src/chipyard.harness.TestHarness.BudaGemminiMesh4RocketConfig/gen-collateral/ | head
grep -l '^module Mesh\b' generated-src/chipyard.harness.TestHarness.BudaGemminiMesh4RocketConfig/gen-collateral/*.sv
grep -c '^module' generated-src/chipyard.harness.TestHarness.BudaGemminiMesh4RocketConfig/gen-collateral/*.sv | tail -1

# 3. LibreLane on the MESH alone (tier 1b), one directory per N.
for N in 4 8 16; do
  d=~/src/buda/flow/librelane/tier1b/n$N; mkdir -p $d
  cp -r generated-src/chipyard.harness.TestHarness.BudaGemminiMesh${N}RocketConfig/gen-collateral $d/
  cp ~/src/buda/flow/librelane/tier1b/mesh_config.json $d/config.json
  (cd $d && librelane --dockerized --run-tag flat config.json)
  python3 ~/src/buda/flow/librelane/tier1a/runtimes.py $d/runs/flat
done
```

Two things to check on the first run, because they are the two places the
recipe is guessing:

* **The mesh module's name.**  `grep -l '^module Mesh'` above says which file
  defines it; if FIRRTL emitted `Mesh_1`-style variants, `DESIGN_NAME` in
  `config.json` must name the one `Gemmini` instantiates (`grep 'Mesh.*mesh'`
  in the `Gemmini*.sv` file).
* **The clock port name.**  Chisel modules expose `clock` and `reset`;
  `CLOCK_PORT` is set to `clock`.  `reset` is synchronous and active-high.

Tier 2 is the same generated design with `DESIGN_NAME: ChipTop` (Rocket +
Gemmini + peripherals, and the Sram22 macros the Sky130 tutorial uses for the
caches and scratchpads) — kept out of tier 1b on purpose, since the mesh has
no SRAMs and so no macro-integration cost to confound the runtime numbers.
